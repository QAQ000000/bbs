# 安全邮箱换绑

2026-09-08，schema 15。Go 只提供 API；确认页面由独立前端实现。

## 接口

所有请求都需要登录 Cookie 和 `X-CSRF-Token`，支持 JSON 或表单。

| 接口 | 字段 | 成功响应 |
| --- | --- | --- |
| `PATCH /api/v1/me` | 可选 `signature`，最多 200 字且受等级限制；省略保持原值 | 200 |
| `POST /api/v1/me/email/change` | `email`、`password`；已启用 2FA 时还需 `code` 或 `recovery` 二选一 | 202，`message`、`expiresIn:1800` |
| `POST /api/v1/me/email/confirm` | `token`，必须在发起换绑的登录会话中提交 | 200，`message` |

`PATCH /me` 不再直接设置或清空邮箱。传入与当前邮箱不同的 `email` 返回 `422 EMAIL_CHANGE_REQUIRED`，整个请求不保存；传入相同邮箱仅作为兼容输入忽略。清空签名需显式传 `signature:""`。

## 流程

1. 用户输入新邮箱和当前密码。启用 2FA 的账号同时提供当前 TOTP 或一个未使用恢复码。
2. 后端锁定账号、重新检查发起会话及当前凭据，原子保存待换绑记录、加密邮件任务和审计。原邮箱及验证状态保持不变。每账号每小时最多 5 次身份验证尝试，失败计数存入数据库。
3. 邮件指向前端 `/settings/email/confirm?token=...`。前端读取登录状态，并在用户确认后向确认 API 提交 token。GET 页面和邮件扫描不会自动执行换绑。
4. 确认 API 在事务内校验 token、发起会话、原邮箱、密码及启用中的 MFA 版本。令牌有效期 30 分钟；新申请替代旧申请。换设备、退出发起会话、改密/重置、账号封禁或变更 MFA 配置后需重新申请。
5. 确认后新邮箱成为已验证的恢复地址；同事务撤销旧邮箱验证令牌及全部旧密码重置令牌、其他设备会话与登录 MFA 挑战，向原邮箱加入安全通知并记录审计。没有原邮箱时跳过旧址通知。任一步失败均回滚，仍可在有效期内重试。

未配置 SMTP 时发起换绑返回 `503 EMAIL_UNAVAILABLE`；不能跳过验证直接修改邮箱。已发起的确认仍可以完成，安全通知由持久队列等待邮件服务恢复。安全邮件不受用户的内容邮件偏好控制。

## 错误与隐私

| 状态 / code | 含义 |
| --- | --- |
| 401 `MFA_INVALID` | 密码、第二因素或会话状态不正确 |
| 403 | 未通过 CSRF |
| 409 `EMAIL_UNAVAILABLE` | 新地址与当前相同，或已被其他账户占用；确认时也重新检查唯一性 |
| 422 `VALIDATION_FAILED` | 邮箱格式不正确 |
| 422 `EMAIL_CHANGE_INVALID` | 令牌无效、过期、已使用或与发起设备/账号状态不符 |
| 429 `MFA_RATE_LIMITED` | 账号身份验证尝试过多 |
| 503 `MFA_UNAVAILABLE` | 已启用 2FA，但密钥缺失或无法解密 |

API 不返回确认令牌；待投递令牌使用 `FORUM_MAIL_KEY` 加密。后台邮件列表不暴露新旧邮箱、密码摘要或令牌。向旧址发送的通知不包含新邮箱或可使用的恢复链接。换绑不移除 2FA，也不提供管理员代关 2FA。

## 验证边界

正式回归覆盖完整 API、回环 SMTP 收信、服务器对象重建后继续投递、旧链接作废、MFA 和恢复码重放、过期/撤销/改密/封禁、并发确认与重置、地址占用、队列及安全通知失败回滚。均使用独立 PostgreSQL 测试库。前端页面、外部 SMTP 和正式部署仍需各自验收。
