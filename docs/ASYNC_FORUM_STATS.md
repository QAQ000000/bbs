# 版块统计异步化设计

## 目标

降低同一主题、同一版块并发发帖时的版块行锁竞争。楼层号、主题状态、积分、悬赏和通知继续在原事务内保持强一致；版块展示型统计允许短暂延迟。

## 统计边界

异步字段：`forums.post_count`、`forums.thread_count`、`forums.last_post_at`、`forums.last_post_uid`、`forums.last_post_author`、`forums.last_thread_id`、`forums.last_thread_title`。

同步字段：`threads.floor_seq`、`threads.post_count`、`threads.last_post_*`、用户发帖数、积分账本、会员经验、订阅事件和通知。版块 `todayCount` 继续从公开楼层实时计算，避免跨日缓存错误。

## 持久化任务

新增 `forum_stat_events`：每条任务包含版块 ID、创建时间、重试次数、下次执行时间和错误状态。当前新主题和回帖在原业务事务内写任务；任务写入失败则整个业务事务回滚。审核、删除、恢复和移动主题目前仍同步校准展示统计。

worker 使用版块行锁和 `SKIP LOCKED` 分批领取任务。每次按版块合并最多 1000 个事件，从当前公开内容重算统计；失败保留事件并指数退避。只删除本批已领取的事件，后续发布事件留给下一批。

## 读取与校准

首页和版块列表读取统计字段时允许延迟；实际延迟取决于任务积压与数据库负载，没有硬性秒级保证。worker 每小时对没有待处理任务的版块入队校准；当前启动时仍执行同步全量重算。

当前已提供 `GET /api/v1/admin/forum-stats`，返回是否启用异步发布、待处理任务数、重试任务数和最老任务年龄。单版块校准已有 `QueueForumStats` 存储层方法，尚未接入管理写接口；当前也没有统计漂移自动告警。

## 启用策略

服务入口固定启用异步发布统计。schema 17 的 `017_async_workers.sql` 正式登记队列与快照结构，重复迁移保留已有任务。开发测试仍可使用同步 Store 夹具，这不代表服务提供运行时回退开关。

## 验收指标

- 同主题 20 并发回帖的 P95/P99 和锁等待相对当前基线下降。
- 任务写入、worker 崩溃、重复消费、数据库重启后不丢统计更新。
- 版块异步字段最终与 `RecomputeForumStats` 完全一致。
- 积分、经验、楼层号、主题计数和通知回归无变化。
- 在持续高负载下任务积压可观测，超过阈值时自动停止扩大消费并报警。
