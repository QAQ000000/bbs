# 版块统计异步化设计

## 目标

降低同一主题、同一版块并发发帖时的版块行锁竞争。楼层号、主题状态、积分、悬赏和通知继续在原事务内保持强一致；版块展示型统计允许短暂延迟。

## 统计边界

异步字段：`forums.post_count`、`forums.thread_count`、`forums.last_post_at`、`forums.last_post_uid`、`forums.last_post_author`、`forums.last_thread_id`、`forums.last_thread_title`。

同步字段：`threads.floor_seq`、`threads.post_count`、`threads.last_post_*`、用户发帖数、积分账本、会员经验、订阅事件和通知。版块 `todayCount` 继续从公开楼层实时计算，避免跨日缓存错误。

## 持久化任务

新增 `forum_stat_events`：每条任务包含版块 ID、创建时间、重试次数、下次执行时间和错误状态。发帖、审核、删除、恢复、移动主题在原业务事务内写任务；任务写入失败则整个业务事务回滚。

worker 使用 `FOR UPDATE SKIP LOCKED` 分批领取任务，同一版块按 ID 顺序处理。处理时从当前公开内容重新计算该版块统计并提交，失败保留任务并指数退避。重复任务通过唯一键或合并窗口去重，不能丢失最后一次状态变化。

## 读取与校准

首页和版块列表读取统计字段时允许最多数秒延迟，主题详情和用户个人统计不依赖异步版块计数。后台增加统计漂移诊断和单版块手动校准接口。worker 每小时抽样校准，启动时不再阻塞整个服务，只将全部版块加入低优先级校准队列。

当前已提供 `GET /api/v1/admin/forum-stats`，返回是否启用异步发布、待处理任务数、重试任务数和最老任务年龄。单版块校准使用 `QueueForumStats` 存储层接口；管理写接口接入前，默认同步模式仍是回退路径。

## 启用策略

第一阶段已实现任务表、worker、重试和校准，异步展示统计默认启用。设置 `FORUM_ASYNC_FORUM_STATS=0` 可紧急回退到同步更新；未设置或设置为其他值均保持异步模式。任务表由当前 schema 的幂等 DDL 创建，因此不增加 schema 版本号。

## 验收指标

- 同主题 20 并发回帖的 P95/P99 和锁等待相对当前基线下降。
- 任务写入、worker 崩溃、重复消费、数据库重启后不丢统计更新。
- 版块异步字段最终与 `RecomputeForumStats` 完全一致。
- 积分、经验、楼层号、主题计数和通知回归无变化。
- 在持续高负载下任务积压可观测，超过阈值时自动停止扩大消费并报警。
