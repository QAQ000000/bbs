# GoBBS 前端页面与交互设计说明

> 设计说明与画板索引：本文保留早期页面设计记录，当前实现和联调状态以 [前端状态](FRONTEND_STATUS.md) 为准。Ardot 后续文件共读取 95 个画板，本文的 85 个页面级 Frame 统计不作为当前总数。

日期：2026-09-28
状态：已形成 Ardot 页面设计基线，主要页面已在 `frontend/` 完成 React/Next.js 实现；本文保留页面清单和交互约束，HTML 样稿不是当前实现前置条件。
Ardot 设计文件：[论坛社区前端页面设计](https://ardot.tencent.com/file/730748088704786?node_id=28%3A2)，共核对 85 个页面级 Frame。
技术基线：React + Next.js App Router + TypeScript；基础组件首选 Arco Design React，后台参考 Arco Pro；Go 只提供 API、SSE、鉴权和受控媒体。

本文用于指导页面设计和 HTML 样稿制作。页面视觉以已确认的 Ardot 社区门户首页设计稿为参考：顶部导航、左侧版块导航、中央信息流、右侧公告与快捷入口、浅灰背景、白色内容区、少量亮蓝强调。接口字段和业务规则以现有 API 文档为准，页面不能自行复制权限或成长规则。

## 1. 设计原则

### 1.1 页面层级

- 公共内容：首页、版块、主题、搜索、标签、公开用户资料。
- 账号流程：登录、注册、验证码、找回密码、邮箱验证、二次验证。
- 用户中心：我的主页、收藏、草稿、通知、订阅、关注 / 粉丝、私信、设置。
- 内容操作：发主题、回复、编辑、附件、举报、投票、悬赏、签到。
- 管理后台：概览、内容审核、版块、标签、用户、会员等级、称号、积分、签到、投票 / 悬赏、通知邮件、系统设置、权限和诊断。

### 1.2 统一视觉

| 项目 | 设计基线 |
| --- | --- |
| 页面底色 | 浅灰，建议 #F5F6F8 |
| 内容面板 | 白色，细边框优先，阴影很轻 |
| 主强调色 | 亮蓝，建议 #165DFF；用于选中、发布、主要确认 |
| 标题文字 | 深灰，清晰的中文无衬线字体 |
| 辅助文字 | 中灰；时间、计数和来源信息降低对比度 |
| 圆角 | 面板约 8px，按钮约 6px；避免全部元素卡片化 |
| 间距 | 以 4px / 8px 为步长，桌面留白充足，手机两侧约 16px |
| 图标 | 线性图标配中文名称；图标按钮必须有可访问名称 |
| 状态色 | 成功、警告、错误、审核状态同时使用文字，不只依赖颜色 |
| 内容密度 | 首页适度紧凑，帖子正文舒展，后台表单和表格更紧凑 |

Arco 组件通过主题变量接入；首页信息流、版块导航、作者资料、楼层、徽章和社区侧栏属于业务组件，自行排版。

### 1.3 全局交互

- 顶部导航固定显示站名、首页、版块、搜索、发布、通知、私信和用户菜单。
- 登录前显示登录 / 注册入口；登录后显示头像、未读数量和个人菜单。
- 页面加载显示骨架或局部加载，不用整页空白。
- 空状态说明原因并给出下一步，例如浏览版块、关注用户、创建主题。
- 错误状态显示中文原因和重试入口；已加载内容保留。
- 写操作完成后使用页面内提示或结果区域，不依赖浏览器 alert。
- API 权限和业务错误以后端返回为准，前端按钮只是当前能力提示。
- 非幂等动作不自动重试；点赞、收藏、关注等超时后先读取真实状态。
- 桌面采用多栏布局，手机改为单列；手机不直接压缩桌面表格。
- 所有页面支持键盘焦点、可见焦点、焦点返回和简体中文文案。

## 3. 公共页面

### PUB-01 首页信息流

**目标**：让用户快速找到感兴趣的主题并进入版块或主题详情。

**布局**：

- 顶部导航：站名、首页、版块、搜索、发布、通知、私信、头像。
- 左栏：版块导航，交流分享、经验教程、问题求助、生活闲聊、站务公告、全部版块。
- 中栏：综合、关注版块、关注的人三个切换；主题摘要连续排列。
- 右栏：社区公告、快捷入口、热门作者或精选版块。
- 手机：单列信息流，顶部切换，底部首页、版块、发布、消息、我的。

**信息流条目**：标题、短摘要、作者、版块、时间、回复数、可选缩略图、等级 / 称号小标记。标题和摘要为视觉主体。

**接口**：GET /api/v1/site、/home、/threads；关注流需要对应聚合接口后再接入。

**状态**：综合流、关注入口未登录、无关注、无内容、加载、失败、SSE 刷新提示。

**验收**：首屏无需 JavaScript 也能阅读公开内容；关注数据按账号隔离；排序名称与后端真实排序一致。

### PUB-02 版块目录

**布局**：顶部导航；中间按分类分组展示版块；每个版块显示名称、说明、主题数、回复数、最新活动；手机按分类折叠。

**操作**：进入版块、搜索版块、关注版块。版块不可见时不在列表显示。

**接口**：GET /api/v1/forums。

**状态**：空分类、无可见版块、加载和失败。

### PUB-03 版块详情

**布局**：面包屑、版块头部、订阅 / 关注按钮、发帖按钮、置顶主题、普通主题列表、右侧规则和版主信息。

**筛选**：最近回复、最新发布、精华、热门；热门明确显示按查看数排序。分页参数写入 URL。

**接口**：GET /api/v1/forums/:fid、/threads?forumId=...；订阅使用对应论坛订阅接口。

**状态**：未登录、已关注、通知关闭、版块无主题、权限限制、分页结束、失败。

**验收**：置顶与普通主题分区；不使用前端循环请求每个主题拼装页面。

### PUB-04 主题详情

**布局**：面包屑、主题标题、首楼、回复分页、右侧作者 / 版块辅助信息。首楼和回复使用清晰楼层结构，不采用聊天气泡布局。

**楼层**：头像、作者、等级 / 称号、楼层号、时间、正文、附件、编辑状态、回复 / 引用 / 点赞操作。

**接口**：GET /api/v1/threads/:tid、/threads/:tid/posts；点赞、收藏、阅读、定位、历史使用对应接口。

**状态**：待审核、已编辑、无附件、回复为空、分页、登录后能力变化、主题关闭、不可见。

**验收**：正文安全渲染 Markdown；引用关系、采纳、投票、悬赏只按后端字段显示。

### PUB-05 / PUB-06 标签目录与标签主题

标签目录支持搜索、分页和标签说明；标签主题页显示标签名称、描述、颜色、主题列表和订阅按钮。

接口：GET /api/v1/tags、/tags/:tagId、/tag-slugs/:slug、/tags/:tagId/threads。

禁用标签仍可显示详情，但新订阅和新绑定遵守后端规则。标签颜色只作辅助，不作为唯一状态表达。

### PUB-07 搜索结果

**布局**：搜索框、内容类型筛选、结果列表、分页 / 游标、无结果说明。

**条目**：主题标题、摘要、版块、作者、时间、回复数、匹配片段。

**接口**：GET /api/v1/search。

**状态**：空关键词、无结果、搜索过期、权限过滤、请求失败。搜索结果默认 noindex，避免筛选 URL 被搜索引擎无限抓取。

### PUB-08 用户公开主页

显示头像、用户名、等级 / 徽章、称号、简介、发帖统计、最近主题和关注 / 粉丝按钮。私信入口不要求互关；屏蔽或账号状态由后端返回处理。

接口：GET /api/v1/users/:id、/users/:id/followers；关注使用 follow 接口。

## 4. 账号与安全页面

### AUTH-01 登录

表单：用户名 / 邮箱、密码、验证码（启用时）、记住设备（若后端支持）。2FA 账号在登录成功后进入独立验证码页，不在登录页堆叠所有字段。

接口：POST /api/v1/auth/login、POST /api/v1/auth/2fa、GET /api/v1/auth/captcha。

状态：密码错误、验证码错误、需改密、需邮箱验证、2FA、账号封禁、站点关闭。

### AUTH-02 注册

字段：用户名、邮箱、密码、确认密码、验证码、同意条款。明确密码规则和用户名冲突错误。

接口：POST /api/v1/auth/register、GET /api/v1/site。

### AUTH-03 / AUTH-04 找回和重置密码

找回页只提交邮箱 / 用户名并显示统一结果；重置页校验链接状态后输入新密码。过期、已使用和被撤销的链接显示清晰说明，不泄露账号是否存在。

接口：POST /api/v1/auth/password/forgot、/password/reset。

### AUTH-05 邮箱验证与换绑确认

验证页显示当前链接状态、成功结果和重新发送入口。换绑流程分为发起、验证新邮箱、确认完成；必须展示旧邮箱恢复链接失效、其他设备退出等结果。

接口：POST /api/v1/auth/email/verify、/me/email/verify-resend、/me/email/change、/me/email/confirm。

### AUTH-06 安装向导

分步骤：数据库 / 站点基础配置、管理员账号、邮件与安全提示、完成检查。禁止在前端显示数据库密码，敏感字段只提交到安装 API。

接口：GET /api/v1/setup、POST /api/v1/setup。

## 5. 用户中心

### MEMBER-01 我的主页

显示头像、用户名、等级进度、徽章、称号、统计、最近主题和最近回复。等级升级规则和权限额度只展示后端返回的结果。

接口：GET /api/v1/me、/me/content。

### MEMBER-02 收藏

主题列表、收藏状态、分页、无收藏空状态。收藏 toggle 超时后重新读取主题状态。

接口：GET /api/v1/me/favorites、POST /api/v1/threads/:tid/favorite。

### MEMBER-03 草稿箱

列表显示主题 / 回复草稿、更新时间、继续编辑、删除。编辑器恢复草稿时提示本地内容与服务端内容的差异。

接口：GET /api/v1/me/drafts、/me/draft；保存和删除使用对应写接口。

### MEMBER-04 通知中心

按未读 / 全部筛选，显示回复、@、采纳、称号、会员、审核、举报和订阅通知。支持单条打开、全部已读和进入来源内容。

接口：GET /api/v1/me/notifications、/notifications/summary；已读使用 notifications/read。

### MEMBER-05 我的订阅

按主题、版块、标签分组；显示通知开关、站内 / 邮件开关、静音时间、取消订阅。新订阅默认开启通知，但用户可以单独关闭。

接口：GET /api/v1/me/subscriptions；订阅使用 thread / forum / tag subscribe 接口。

### MEMBER-06 关注与粉丝

提供“我关注的”“关注我的”“对方的粉丝”三个列表；显示头像、用户名、等级、关注时间、关注 / 取消关注按钮。

接口：GET /api/v1/me/following、/me/followers、/users/:id/followers；POST /api/v1/users/:id/follow、DELETE 同路径。

### MEMBER-07 私信

左侧会话列表，右侧消息历史；手机切换为会话列表 / 消息详情两级页面。显示发送方、时间、已读状态、屏蔽状态。

规则：无需互关；对方回复前只能发送首条；对方回复后解除限制；被屏蔽后发送被拒绝。首条限制、屏蔽和频率错误必须原样转成中文状态。

接口：GET /api/v1/me/conversations、/conversations/:cid/messages；发送、已读、屏蔽使用对应接口。

### MEMBER-08 安全设置

分为密码、邮箱、2FA、设备会话、注销账号。2FA 页面展示二维码 / 密钥、验证码、恢复码一次性展示和下载 / 复制提示；设备会话展示当前设备、位置、最后活动和撤销按钮。

接口：GET /api/v1/me/sessions、/me/2fa；session 与 2FA 使用对应接口。

### MEMBER-09 资料设置

头像、用户名 / 昵称可编辑范围、简介、邮箱状态、通知偏好、显示设置。危险操作单独分区并二次确认。

接口：PATCH /api/v1/me、/me/avatar、/me/notification-preferences、DELETE /api/v1/me。

## 6. 内容操作页面

### CONTENT-01 发布主题

字段：所属版块、标题、标签、Markdown 正文、附件、投票 / 悬赏扩展、预览、草稿、提交。

右侧或底部显示版块规则、剩余字数、附件状态和审核提示。提交后显示主题 ID、待审核状态或成功跳转，不假设返回 HTML。

接口：POST /api/v1/threads、POST /api/v1/uploads、草稿接口。

### CONTENT-02 回复主题

复用 Markdown 编辑器、引用、附件、草稿和预览；显示主题是否关闭、是否需要审核、剩余字数和回复权限。

接口：POST /api/v1/threads/:tid/posts。

### CONTENT-03 编辑内容

显示历史版本信息、当前版本号、冲突提示和本地草稿恢复。编辑标签单独处理首楼版本。

接口：PATCH /api/v1/posts/:pid、/posts/:pid/history、/threads/:tid/tags。

### CONTENT-04 投票

普通主题内嵌投票卡：问题、单选 / 多选选项、截止时间、参与状态、结果图表。未投票时突出提交，已投票后显示结果；不设计改投，除非后端以后新增规则。

### CONTENT-05 悬赏

显示悬赏积分、当前状态、截止时间、采纳入口、冻结 / 结算 / 退款状态。积分不足、主题关闭、超时退款和已采纳状态要有明确反馈。

### CONTENT-06 签到

显示今日状态、连续签到天数、经验 / 积分奖励、历史摘要和规则说明。重复签到显示已完成，不重复提交。

### CONTENT-07 排行榜

首版可显示积分 Top 100 和站点统计快照；区分统计日期、更新时间和快照过期状态。没有公开榜单规则时，不在前端编造复杂筛选维度。

## 7. 管理后台

后台采用 Arco Pro 参考的左侧导航、顶部工具栏、面包屑、表格和抽屉表单；不把后台仪表盘样式直接用于前台。

### ADMIN-01 概览

卡片显示可用站点统计、待审核数量、队列状态、搜索 / 数据库健康摘要。所有指标显示统计时间和来源，异常使用红色状态和详情入口。

接口：GET /api/v1/admin、/admin/diagnostics、/admin/forum-stats、/admin/search-stats。

### ADMIN-02 审核与举报

分栏或标签展示待审主题、回复、举报；操作为通过、删除、驳回 / 结案，支持备注和详情抽屉。重复处理显示已处理，不自动重复提交。

接口：GET /api/v1/admin/moderate、POST /admin/moderate/thread、/moderate/post、/admin/report/handle。

### ADMIN-03 分类与版块

树形分类和版块列表，支持新增、编辑、删除、移动、版主、访问权限和排序。删除 / 移动等危险操作二次确认并显示影响范围。

接口：GET /api/v1/admin/forums；写操作使用 admin forums / cats 接口。

### ADMIN-04 标签管理

表格支持搜索、状态、名称、slug、颜色、描述、版本；编辑保存需处理版本冲突。显示别名保留提示和绑定主题数量。

接口：GET /api/v1/admin/tags、POST /api/v1/admin/tags、PUT /api/v1/admin/tags/:tagId。

### ADMIN-05 用户与封禁

用户搜索、用户详情、分组、封禁 / 解封、屏蔽、删除；危险操作显示原因、期限和影响。权限按钮由后端能力决定。

接口：GET /api/v1/admin/users 及用户管理写接口。

### ADMIN-06 会员等级

等级列表、经验门槛、权限 / 额度、徽章、启用状态、预览和人工调整。新增等级后，对超过经验上限的用户按当前经验匹配最高可达等级，不要求用户重新获得经验。

接口与字段见 MEMBERSHIP.md；不在前端复制升级算法。

### ADMIN-07 称号与条件

称号列表、条件组、达成统计、有效期、撤销 / 补发、佩戴状态和审计。条件可以是发帖、回复、获赞、精华、采纳等事件，不把称号等同于会员等级。

接口与字段见 TITLES.md。

### ADMIN-08 投票、悬赏、签到

使用分标签页：投票规则、悬赏积分规则、签到奖励。每项显示启用状态、权限、额度、超时 / 退款策略和修改审计。

接口与字段见 ENGAGEMENT_FEATURES.md、POINTS.md。

### ADMIN-09 排行榜与报表

显示快照列表、统计日期、刷新时间、过期标记、保留期和清理结果。报表与排行榜分开，避免把快照当实时查询。

接口：GET /api/v1/admin/analytics/:name、/admin/forum-stats、/admin/search-stats。

### ADMIN-10 邮件与通知队列

列表显示任务类型、收件人摘要、状态、重试次数、下次重试时间、最后错误；支持查看详情和手动重试。不能在页面显示完整敏感邮件内容。

接口：GET /api/v1/admin/email-jobs、POST /admin/email-jobs/:jobId/retry。

### ADMIN-11 站点设置

分组表单：站点信息、注册、上传、邮件、通知、搜索、内容、审核、会员、积分、签到和安全。配置 schema、当前值、默认值、版本、保存结果和审计入口同时展示。

接口：GET /api/v1/admin/settings、/settings/schema、/settings/status；PUT / PATCH / POST 按当前契约提交。

### ADMIN-12 权限、会话与诊断

权限矩阵、当前管理员会话、设备会话、队列、数据库和搜索诊断。二次验证、初始密码修改和权限不足状态必须有独立页面反馈。

## 8. 响应式和无障碍

### 桌面

- 首页三栏，版块页和帖子页主栏 + 辅助栏。
- 后台左侧导航 + 内容区 + 抽屉详情。
- 表格支持横向滚动或列优先级，不强行缩小文字。

### 平板

- 左栏折叠为入口，右栏下移或收起。
- 信息流保持标题和摘要宽度，操作按钮减少文字但保留 aria-label。

### 手机

- 首页单列，底部五项导航。
- 版块页先显示版块头部和主题列表，规则 / 版主改为折叠区域。
- 帖子页作者信息压缩到楼层头部，正文保持阅读宽度。
- 私信切换为会话列表和消息详情两个状态。
- 后台表格改为卡片或字段列表，危险操作固定在底部操作区。

### 无障碍

- 所有图标按钮有中文名称。
- 键盘可访问菜单、标签、弹窗、分页和编辑器。
- 焦点进入弹窗后不逃逸，关闭后回到触发按钮。
- 错误信息关联到字段，不能只用红色边框。
- 动态通知使用可读的状态提示；SSE 只提示刷新，不替代页面数据。

## 9. HTML 样稿交付要求

你后续提供 HTML 时，每个页面建议单独一个文件或目录，并注明：

- 页面 ID，例如 PUB-01、MEMBER-07、ADMIN-02。
- 桌面和手机宽度。
- 使用的占位数据。
- 可点击交互和未实现项。
- 需要后端真实接入的字段。
- 与本文不一致的地方。

我收到 HTML 后会按页面 ID 逐项核对：布局、中文文案、响应式、组件状态、接口映射、权限边界和视觉一致性，再给出需要调整的 CSS / 结构 / API 接入清单。

## 10. 第一批制作顺序

1. PUB-01 首页信息流（桌面 + 手机）。
2. PUB-03 版块详情。
3. PUB-04 主题详情。
4. AUTH-01 登录、AUTH-02 注册。
5. CONTENT-01 发布主题、CONTENT-02 回复。
6. MEMBER-04 通知、MEMBER-07 私信、MEMBER-08 安全设置。
7. ADMIN-01 概览、ADMIN-02 审核、ADMIN-03 版块。
8. 其余用户中心、互动和配置页面。

前四个页面先统一导航、主题变量、按钮、标签、输入框、弹窗和加载 / 空 / 错误状态，再扩展页面数量。这样 HTML 样稿可以直接转成 React 组件，而不是先做大量一次性页面。
