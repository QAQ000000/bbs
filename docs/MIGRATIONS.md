# 数据库迁移与派生数据维护

2026-09-28，当前 schema 20。本文件对应当前源码；旧二进制不一定具有以下命令。部署前先核对发布版本。

## 启动配置

所有连接数据库的运行模式必须显式设置 `FORUM_DSN`。空值或全空白会立即报错，不再使用内置账号密码或 PostgreSQL 隐式默认连接。连接池上下限仍按原规则校验。`-version`、`-import-smileys` 无需数据库。

普通服务仍自动迁移，保持现有启动方式兼容。新增独立入口：

```bash
# 在已通过受限环境文件导出 FORUM_DSN 的终端执行
./bin/forumd -migrate -migration-timeout 5m

# 迁移成功后再由现有服务管理器启动普通 forumd
```

`-migrate` 成功退出码为 0，不启动 HTTP、业务 Worker、种子数据或派生数据全量修复。`-migration-timeout` 默认 5 分钟，限制迁移事务与等待迁移锁的总时间；数据库建立连接发生在该计时之前。大表升级应按演练耗时调整。`-seed`、`-check-backup`、`-migrate`、`-enqueue-derived-repair`、`-import-smileys` 互斥；非法组合或非正超时退出码为 2。

## 迁移事务与锁

实现位于 [migrate.go](../internal/db/migrate.go)：

1. 开始一个 READ COMMITTED 事务，先获取固定的 PostgreSQL 事务级 advisory lock。同库、采用该实现的迁移进程串行执行，后进入者获取锁后重新读取版本。
2. 只有缺少 `schema_migrations` 时才执行完整 `assets/db/schema.sql`，作为新库或无版本账本旧库的兼容初始化。已有账本的库不再重放完整 schema。无版本旧库仍须先在副本演练，不能将幂等 SQL 视为任意旧结构的兼容承诺。
3. 要求版本账本从 1 连续到当前版本。空账本、缺号或高于当前二进制支持的版本均拒绝升级；不自动补号或删记录。
4. 依次执行未应用的编号迁移，并在同一事务写入各版本记录。全部成功后一次提交；任意 DDL、数据变更或版本登记失败，整个本次批次回滚。
5. 事务级锁随提交、回滚或连接终止释放；取消等待不会执行迁移。只有提交成功后才输出“已应用编号迁移”日志。

已达当前版本的正常重启只检查账本，不对业务表执行 schema DDL。这个锁只协调迁移器，不阻止在线业务请求，也不协调仍使用旧迁移实现的进程。升级仍按维护窗口规划。

所有版本的新增表、列、约束、索引及必要数据转换都必须进入编号迁移，并同步更新完整 schema；不能只修改 schema.sql。新库会执行完整 schema 和编号迁移，因此编号 SQL 仍须兼容这种初始化路径。迁移文件一经发布不修改历史语义，修正通过新版本追加。

本实现要求迁移可在事务中运行，不支持 `CREATE INDEX CONCURRENTLY`、`VACUUM` 等事务外操作。schema 16 的普通建索引仍可能阻塞写入；单次事务批量升级也可能延长锁持有时间，应先用数据副本测量。

## 互动功能升级（18–20）

018 建立投票与独立版本化互动配置，为会员矩阵补入四个动作并保留自定义布尔值；019 建立悬赏持久状态，沿用不可变积分账本；020 建立按用户/自然日唯一的签到记录。完整 schema 与编号迁移均已同步。

已有 17 库升级只执行缺失编号迁移；重启不重置会员/互动配置、积分或历史记录。当前健康端点应报告 schema 20。悬赏表有意保留已删除主题的 ID，退款 Worker 会处理过期/删除/物理清理后的活动记录；不能手动删记录代替退款。

## 显式排入派生数据修复

普通启动不再同步扫描全部帖子重建搜索索引，也不再同步重算全部版块统计。正常发帖、编辑、审核和删除沿用持久事件及现有 Worker；版块周期校准仍保留。

在导入历史数据、恢复备份、需要全量重分词或确认派生数据损坏后，可显式执行：

```bash
./bin/forumd -enqueue-derived-repair -migration-timeout 10m
```

该命令先完成迁移，再在另一个事务中为现存帖子排入搜索任务，并为尚无统计事件的版块排入校准事件，然后退出。修复事务单独使用上述超时时长。日志中的 `searchJobs`、`forumJobs` 是本次新增任务数，**不是已修复数量**。

- 已存在的搜索任务保留首次时间、失败次数和下一次重试时间，不因全量修复重置退避。
- 多个此维护命令之间串行排队；普通业务发布和周期校准仍独立运行，允许冗余但可重算的版块事件。
- 搜索与版块任务同一事务入队，失败不留下半套修复任务。
- 搜索消费者在其正常锁和可见性校验下读取当前正文，避免维护命令用过期正文直接覆盖索引。
- 命令不会自行消费队列。需要普通 `forumd` Worker 运行；有积压、重试或持续写入时不能假定立即完成。
- 全量入队会扫描帖子表并新增任务，执行前预估队列和数据库空间；高负载站点选择维护窗口。

确认搜索与版块队列的待处理数、最老年龄和重试状态，再抽检目标内容搜索结果及版块计数。诊断 API 为 `/api/v1/admin/search-stats`、`/api/v1/admin/forum-stats`，均需管理员会话。持续有新任务时，要结合具体修复对象核对，不能只凭队列瞬时为零判定所有历史数据正确。

## 升级失败与回退

迁移事务未提交时会回滚；提交后的数据库升级不会因替换旧二进制而撤销。当前实现遇到超出自身支持范围的账本会拒绝启动，因此不能把 `gobbsctl` 的二进制回退等同于数据库可回退。升级前保留数据库、媒体文件及邮件/MFA 密钥的备份，并演练与旧版本兼容的恢复方式。

账本异常应先备份并对照真实表结构和已发布迁移检查，禁止为“让启动通过”直接补删版本号。

## 验证入口

`bash scripts/verify-local-backend.sh test` 使用一次性 PostgreSQL 集群。新增迁移回归覆盖六个迁移器同时启动、正常重启不触碰被锁业务表、登记失败时 DDL 回滚、初始化失败清理、锁等待取消，以及空/缺号/未来版本账本拒绝。现有历史版本升级和重启保留数据测试继续运行。维护测试覆盖重复入队保留重试状态及故障回滚。

这些验证不替代生产数据副本上的升级耗时、磁盘容量和备份恢复演练。
