# 前端 UI 与交互交付规范

日期：2026-09-28。适用于 React + Next.js + TypeScript 前端。当前首页视觉基线来自用户确认的社区门户渲染稿，基础组件首选 Arco Design React，并参考 Arco Pro 的设计变量与后台能力。

## 结论

建议采用 **Figma（或同等设计工具）+ Markdown** 的组合：

- Figma 负责页面结构、视觉层级、组件状态和交互连线，方便快速调整和评审。
- Markdown 负责开发约束、接口映射、状态规则、响应式要求和验收标准，作为工程可追踪的文字契约。
- 渲染图只作为视觉参考，不能替代可交互原型、接口契约或无障碍验收。

如果暂时不使用 Figma，首版也可以用已确认的渲染图、页面截图和本文完成开发；但在页面超过首页、版块页、帖子页后，建议尽快建立 Figma 文件，否则组件状态和页面差异容易失控。

## Figma 文件建议

不要先画完整后台和全部异常页面。先建立以下页面或画板：

1. `00-视觉基线`：颜色、字体、间距、圆角、分隔线、阴影、头像、等级 / 称号徽章。
2. `01-基础组件`：按钮、搜索框、标签切换、公告项、快捷入口、分页、弹窗、提示、表单控件。
3. `02-首页`：桌面三栏、登录状态、未登录状态、关注流空状态、加载和失败状态。
4. `03-版块页`：版块头部、订阅、发帖、筛选、置顶、主题列表和分页。
5. `04-帖子页`：首楼、回复、引用、点赞、收藏、关注、私信、编辑和举报入口。
6. `05-移动端`：首页单列、底部导航、主题详情和编辑 / 回复入口。
7. `06-后台`：Arco Pro 参考的导航、表单、表格、审核队列和配置页。

每个关键组件至少展示默认、悬停、聚焦、按下、禁用、加载、成功、失败和空状态。移动端单独排版，不直接把桌面三栏缩小。

## Markdown 交付内容

每个页面在 Markdown 中记录：

| 项目 | 必须写清的内容 |
| --- | --- |
| 页面目标 | 用户在页面上要完成的任务和主要入口 |
| 数据来源 | 使用的 API、分页方式、登录要求和缓存边界 |
| 组件 | 页面使用的基础组件和论坛业务组件 |
| 状态 | 加载、空数据、未登录、无权限、失败、冲突和成功状态 |
| 操作 | 点击、提交、取消、返回、重试和跳转规则 |
| 响应式 | 桌面、平板、手机的布局变化和隐藏 / 折叠规则 |
| 文案 | 中文按钮、提示、错误和确认文案 |
| 验收 | 开发完成后可逐项检查的结果 |

接口引用使用实际路由和字段，例如主题列表、关注流、订阅、私信和通知不能只写“调用后端获取数据”。业务权限仍以后端返回和后端校验为准。

## 首批页面交互契约

### 首页

- “综合”“关注版块”“关注的人”是三个信息流入口；登录前点击关注入口显示登录引导。
- 综合流使用后端实际排序名称；当前按最后回复排序时，界面不能写成“最新发布”或“推荐”。
- 关注流按账号隔离；无关注关系和无可见内容分别展示不同空状态。
- 首屏可以 SSR；继续加载使用游标或分页接口，失败时保留已读内容和重试入口。

### 版块页

- 显示版块名称、说明、统计、关注状态、发帖入口、置顶主题和普通主题。
- “最近回复、最新发布、精华、热门”必须映射到后端支持的排序参数。
- 关注通知的开关和取消关注是不同操作；新订阅默认开启通知的规则由后端执行。

### 帖子页

- 首楼和回复按后端分页返回；引用、采纳、投票、悬赏、点赞和收藏只在能力字段允许时显示。
- 编辑遇到版本冲突时保留本地内容，提示用户重新读取；点赞 / 收藏超时后读取实际状态，不能盲目重试 toggle。
- 私信无需互相关注，但首条消息限制、对方回复解锁和屏蔽规则由后端返回错误决定。

## 设计到代码的拆分

### 主题变量

先从渲染稿抽取颜色、字号、行高、内容宽度、栏宽、间距、圆角、边框和阴影。主题变量由前端统一维护，Arco 组件通过主题机制接入；论坛业务组件不要在各自文件里重复写颜色值。

### 基础组件

优先使用 Arco Design React：按钮、输入、选择器、弹层、提示、分页、表单、表格和导航。若默认样式与渲染稿不一致，通过主题变量或局部封装修正。

### 业务组件

自行实现：信息流主题摘要、版块导航、作者信息、等级 / 称号徽章、楼层、引用、订阅状态、关注状态、通知入口和私信会话。Arco Pro 的后台布局只作为后台参考，不直接套进前台首页。

## 验收顺序

1. 先验收首页桌面布局和中文内容密度。
2. 再验收首页手机单列、底部导航和三类信息流切换。
3. 再验收版块页、帖子页和登录前后的状态变化。
4. 最后接后台表单、表格、审核和设置页面。

每轮只调整一类问题，例如只改颜色、只改密度或只改导航，避免无法判断改动效果。Figma 与实现不一致时，先记录差异，再决定是修设计稿还是修代码；不要通过临时 CSS 覆盖长期积累差异。

页面总表和具体页面设计见 [前端页面与交互设计说明](FRONTEND_PAGE_DESIGN.md)。
