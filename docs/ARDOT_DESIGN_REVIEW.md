### 运行态差距

1. **移动登录 / 注册是首要缺口**：设计稿的移动认证不是桌面表单的简单缩放，当前实现缺少移动专用头部、品牌识别、返回入口、底部安全提示和社交登录区。
2. **后台移动端仍偏“压缩桌面”**：虽然导航横向溢出已处理，但权限、诊断、设置等页面的字段密度、表格呈现、分组折叠和操作栏还未完全按 375px 画板重排。
3. **安装向导存在产品契约差异**：设计稿 `AUTH-06` 是四步数据库安装向导；当前是安全的单步安装表单。它不是纯 CSS 偏差，不能仅靠调间距解决。
4. **后台邮件与权限页面存在数据边界差异**：`ADMIN-10` 的收件人细节受当前 API 字段限制；`ADMIN-12` 在实现中拆成权限、会话和诊断路由，因此页面数量和稿件不完全一一对应。
5. **资源复用有限**：PPTX 解压后主要是头像插画资源，现有实现已有同类头像占位和后端头像地址，暂未强行复制素材；品牌 Logo、运营横幅等仍应由站点配置或正式资源提供。

### HTML 稿的复用边界

- 页面 HTML 是设计工具导出的绝对定位层，包含大量 `clip-path`、内联坐标和 PUA 图标字形；直接替换 React 页面会失去响应式、权限和真实接口数据。
- `img46.png` 是首页社区横幅，可以作为站点公共静态资源安全复用；其余 PNG 主要是头像或内容缩略图，当前页面应优先使用 API 返回的头像、封面和权限结果。
- `font_f*.woff2` 主要服务导出稿的图标字形，不应直接设为业务正文默认字体；现有前端继续使用系统中文字体和 Arco 图标组件。

## 页面与 API 差异

以下内容在视觉稿中出现，但接入时必须按当前后端能力处理：

| 设计内容 | 接入判断 |
| --- | --- |
| 首页“最新 / 热门”、热门话题、热门作者 | 当前后端有最近活跃主题、站点统计和部分排行榜快照；热门话题 / 热门作者需要明确查询接口后再接真实数据，不能用前端静态排序冒充全站榜单 |
| 首页横幅 / 社区介绍 | 可作为站点配置或运营内容；当前 `/home` 不是完整横幅管理接口，先用站点配置或占位数据，避免新增未经确认的运营模型 |
| “标签”与“排行榜”顶级导航 | 标签已有目录和主题接口；公开积分余额榜已接入，热门作者 / 热门话题 / 周期榜仍需先定义规则 |
| 帖子附件下载 | 后端已有受控上传 / 媒体访问，前端必须使用返回地址和权限结果，不能拼接未授权文件 URL |
| 关注版块 / 关注的人信息流 | 已通过 `/api/v1/me/feed/forums` 与 `/api/v1/me/feed/users` 提供聚合内容流，不能由浏览器循环请求后拼页 |
| 投票、悬赏、签到 | 第一版业务 API 已有；页面中的结果、积分余额、截止、结算 / 退款状态以后端返回为准 |
| 邮件队列、搜索服务、数据库状态 | 后台设计已有诊断区；仅显示 `/admin/diagnostics` 等接口返回结果，不根据静态指标自行计算健康状态 |
| 管理员邮箱、IP、统计数字 | 设计稿为占位数据。真实实现需遵守后端脱敏和权限范围，不直接照搬示例值 |

## 需要在 HTML 样稿中重点确认

1. 首页主题卡的摘要、缩略图、标签和互动计数在长中文下是否仍保持稳定高度。
2. 版块页的筛选、置顶、分页与关注通知设置是否有明确反馈。
3. 主题页的首楼、回复、引用、采纳、附件和底部回复输入是否能对应真实能力字段。
4. 登录后的二次验证、初始密码修改、权限不足和站点关闭是否使用独立状态页。
5. 私信“首条限制 / 对方回复解锁 / 屏蔽拒收”是否能清楚解释错误，不泄露对方隐私。
6. 手机端底部导航、键盘弹出、长文本滚动、私信二级页面和后台表格折叠。
7. 后台所有危险动作的确认、版本冲突、失败重试和成功反馈。

## 实现建议

- 使用 Arco Design React 实现按钮、输入框、标签、弹层、分页、表单、表格和导航基础能力；不直接套用 Arco Pro 的后台首页模板到论坛前台。
- 自定义实现首页主题卡、版块导航、作者信息、等级 / 称号徽章、楼层、引用、投票卡、悬赏卡、私信会话和诊断摘要。
- 以 Ardot 的 `Noto Sans SC`、亮蓝主色、浅灰背景和 1440 / 375 画板作为主题变量来源。
- HTML 样稿提交时保留画板名称或页面 ID，例如 `PUB-01`、`MEMBER-07`、`ADMIN-02`，便于逐页核对。
- 设计文件有页面，但不代表每个页面都已生产部署；缺少 API 的区域在实现清单中标为“待补接口”，已实现页面以 `frontend/` 当前代码和状态文档为准。
