# 社区扩展功能实施方案

2026-09-07。本文记录标签、订阅、关注/粉丝、私信、积分悬赏、签到排行榜、设备会话、2FA 和持久邮件队列的已确认规则。实现按阶段推进，所有写入使用 API 和数据库事务，Nuxt 只负责展示。

实施进度：schema 9 已接入标签、关注/粉丝、三类订阅分发、私信首条限制/屏蔽/已读。实际 API 和未完成边界以 [COMMUNITY_API.md](COMMUNITY_API.md) 为准。下面的数据模型、奖励数值和开发顺序仍属于目标方案，不能作为已经完成的验收记录。投票、积分/悬赏、签到/排行榜、设备会话、2FA 和持久邮件队列尚未实现。

## 已确认产品规则

- 订阅创建后默认开启站内通知和邮件通知；用户可以分别关闭两种通知。
- 私信不要求互相关注。新会话发送首条消息后，在接收方回复前，发送方只能发送这一条消息。
- 接收方回复后，双方进入正常交流状态。
- 接收方可以屏蔽发送方；屏蔽后发送方的任何新私信都拒绝，不能通过新建会话绕过。
- 悬赏使用独立积分，不复用经验值。经验和积分可以由同一行为同时产生，但分别记账，积分奖励默认低于经验奖励。

## 阶段一：关系、订阅与私信

### 关注/粉丝

`user_follows(follower_id, following_id, created_at)`，联合主键防重复，禁止关注自己。取消关注为幂等操作。拉黑或注销时关系失效；关注动态不等于订阅全部内容。

接口：

- `POST /users/{id}/follow`
- `DELETE /users/{id}/follow`
- `GET /me/following`
- `GET /users/{id}/followers`

### 订阅

分别保存主题、版块和标签订阅。订阅默认 `enabled=true`、站内通知开启、邮件通知开启。发帖时按“提及、指定回复、主题作者、订阅者”顺序去重，同一用户同一帖子只生成一条通知。订阅者必须拥有当前内容访问权限。

### 标签

标签、主题标签关联、标签别名和禁用状态独立建表。主题最多 8 个标签，标签名和 slug 规范化并唯一。标签筛选继续套用版块权限；禁用标签不影响历史主题展示，可禁止新使用。

### 私信

采用会话、成员、消息三层模型。一对一会话首版即可。会话成员保存屏蔽状态和已读位置，会话状态保存发起者首条消息及接收方回复时间。

发送消息必须在事务中锁定会话并依次检查：屏蔽、首条消息限制、账号状态、频率和内容规则。错误码固定为 `MESSAGE_BLOCKED`、`MESSAGE_REPLY_REQUIRED`、`MESSAGE_RATE_LIMITED` 等。新会话和消息均限流，消息支持举报与敏感词检查。

## 阶段二：积分、悬赏、签到、排行榜

积分单独使用账户和流水账本：余额可重算，冻结余额用于悬赏。禁止直接修改余额；扣减、冻结、发奖、退款都必须在同一事务中完成，并使用业务幂等键。

初始行为奖励建议：发主题 10 经验 + 1 积分、发回复 3 经验 + 1 积分、被采纳 30 经验 + 10 积分、获赞 2 经验 + 1 积分、签到 5 经验 + 1 积分。数值全部进入后台配置。

悬赏流程为创建冻结、提交回答、作者采纳、积分转账；取消或超时退款。创建者不能采纳自己的回答，重复采纳和重复转账由唯一约束阻止。

签到使用 `(uid, date)` 唯一记录，日期按站点时区计算。连续签到、补签和奖励调整均留有流水。排行榜按小时或每日生成快照，不在请求时扫描大表；支持经验、发帖、获赞、采纳、签到和悬赏贡献榜。

## 阶段三：设备会话和 2FA

扩展现有 sessions 表，记录设备名、User-Agent、脱敏 IP、最后访问时间、过期和撤销时间。提供会话列表、单设备撤销、全部撤销和设备重命名。原始 token 永不返回；改密、封禁和注销立即撤销会话。

2FA 首版只实现 TOTP。密钥加密存储，恢复码只展示一次并只存哈希。启用、关闭、恢复码使用和异常失败均写审计日志；登录密码正确后返回 `MFA_REQUIRED`，通过 TOTP 或恢复码后才创建完整会话。

## 阶段四：持久化邮件队列

新增 `email_jobs`，保存模板名、收件人、参数、状态、重试次数、下一次执行时间、错误和幂等键。业务事务只写任务，不同步发送邮件。worker 使用 `FOR UPDATE SKIP LOCKED` 批量领取，失败指数退避，超过次数进入死信状态。

验证邮件和密码找回邮件高优先级；@、回复和订阅通知普通优先级；运营邮件低优先级。SMTP 凭据不进入任务 payload，后台可查询失败任务并手动重试。

## 开发顺序和验收

1. 持久化邮件队列和通知发送抽象。
2. 关注/粉丝、订阅、标签及通知去重。
3. 私信会话、首条限制、回复解除限制和屏蔽。
4. 设备会话管理。
5. TOTP 2FA。
6. 积分账户、流水和后台配置。
7. 悬赏、签到、排行榜。

每个阶段独立迁移和回归测试，使用 `gobbs_test_` 数据库。验收重点包括并发幂等、权限变化后的通知过滤、屏蔽绕过、余额重算、重复领奖、任务重试和进程重启恢复。生产环境不在开发阶段执行迁移。
