# 持久化邮件队列

站点名称现由 worker 在准备发送时读取当前站点设置，后台改名后邮件标题和落款随之更新；SMTP、发件地址及站点外部 URL 仍使用部署配置。配置读取失败会延后投递，不使用启动名称冒充当前配置。配置规则见 [站点配置 API](SETTINGS.md)。

2026-09-08 更新：schema 10 引入持久队列，schema 15 新增安全邮箱换绑邮件。本文描述已实现的后端能力；前端管理界面尚未开发。

## 配置

SMTP 仍通过 `FORUM_SMTP_HOST/PORT/USER/PASS/FROM` 配置。未配置 HOST 时不发送邮件，注册邮箱验证门槛继续自动关闭；已有任务仍按有效期清理。邮箱换绑要求邮件验证，未配置时拒绝新申请；已有申请确认产生的安全通知仍持久入队。

启用 SMTP 时必须设置 `FORUM_MAIL_KEY`：32 字节随机密钥的 64 位十六进制编码，可用 `openssl rand -hex 32` 生成。密钥放在受限的服务环境配置中，与数据库备份分开保管，不能提交到代码仓库。缺失或格式错误会阻止服务启动。

该密钥用于 AES-256-GCM 加密待发送的验证/找回令牌，不参与 SMTP 认证。重启和多实例部署必须使用相同密钥。更换密钥前应排空待发送认证任务；直接更换会使旧任务无法解密，用户需重新申请邮件。`FORUM_SITE_URL` 必须是前端公开地址，前端负责 `/verify?token=...` 和 `/reset?token=...` 页面，再调用验证/重置 API。

## 已接入流程

| 来源 | 事务边界 | 有效期 |
| --- | --- | --- |
| 注册邮箱验证 | 用户、验证令牌、邮件任务共同提交 | 24 小时 |
| 重发邮箱验证 | 覆盖验证令牌与新任务共同提交 | 24 小时 |
| 忘记密码 | 重置令牌与邮件任务共同提交；保持统一响应防止枚举账号 | 15 分钟 |
| 换绑确认 `email_change` | 当前凭据验证、待换绑记录与新邮箱邮件任务共同提交 | 30 分钟 |
| 换绑提醒 `email_changed` | 新邮箱生效、旧恢复令牌撤销与旧址通知共同提交 | 7 天 |
| @ 提及、指定回复、主题作者回复 | 站内通知与邮件任务共同提交 | 7 天 |
| 主题/版块/标签订阅 | 分发去重记录、站内通知、邮件任务和事件游标共同提交；支持仅邮件订阅 | 7 天 |

只保存模板种类、版本、收件地址和业务引用；通知正文在发送时读取当前内容。不会持久保存 SMTP 密码或原始认证令牌。模板版本目前为 1，不包含运营群发或私信邮件。

入队不等于发送成功。发送前重新核验账号封禁状态、当前邮箱、令牌有效期和是否已消费。内容邮件还检查通知偏好、帖子/主题删除与审核状态、收件人的最新会员与版块访问权限；订阅邮件检查是否仍订阅、是否静音以及该订阅的邮件开关。不再符合条件的任务取消。

换绑确认另行核验待换绑的新邮箱、密码/MFA 版本和发起会话；旧址安全通知按事务中保存的原邮箱投递，不要求与当前邮箱一致。前端需承接 `/settings/email/confirm?token=...`，调用 [安全邮箱换绑](EMAIL_CHANGE.md) 中的确认 API。

## 执行和恢复

- `forumd` 启动两个邮件 worker，使用 `FOR UPDATE SKIP LOCKED` 领取任务，验证/找回任务优先。HTTP 请求只写数据库，不等待 SMTP。
- 领取租约为 2 分钟，单次准备和发送总期限 75 秒，SMTP 会话最多 60 秒。进程中断后的超时租约可以重新领取；版本号防止旧 worker 覆盖新执行结果。
- 临时失败自动退避：30、60、120、240、480、960、1920 秒，最多尝试 8 次；SMTP 5xx 直接进入 `dead`。重新领取崩溃任务也计入尝试次数。
- 状态为 `pending`、`sending`、`sent`、`dead`、`cancelled`。过期任务取消，不允许后台延长令牌寿命。定时维护每分钟运行，未配置 SMTP 也执行清理。
- 发送成功或取消后删除令牌密文；失败任务保留至过期，过期清除密文。终态记录在有效期结束 30 天后删除。
- 错误仅记录 `smtp_451`、`smtp_550`、`transport_error`、`preparation_failed` 等分类，不保存 SMTP 服务器返回的原始诊断文本。

SMTP 与数据库无法原子提交：SMTP 接受邮件后、任务标记成功前进程崩溃，恢复时可能重复发送。因此实现的是可恢复的至少一次尝试，不保证恰好一次投递，也不能证明进入用户收件箱。任务使用稳定的 Message-ID，数据库按用户和帖子去重。SMTP 已确认 DATA 接收后，QUIT 失败不会触发重发。现有 STARTTLS 和可选认证方式保持不变。

## 后台 API

均要求已登录、后台访问权限及 `email.manage` 权限点，默认仅管理员拥有；该权限可通过既有权限矩阵调整。

`GET /api/v1/admin/email-jobs?status=dead&before=123`

- `status` 可省略，支持五种任务状态；`before` 为上一页的游标。
- 返回 `items`、各状态全量 `counts`、`nextBefore` 和 `smtpEnabled`。每页最多 50 条，按 ID 降序；无下一页时 `nextBefore` 为空字符串。
- 任务包含字符串 `id` / `userId`，以及 `kind`、`status`、`attempts`、`retries`、`version`、`nextAttemptAt`、`expiresAt`、`createdAt`、`sentAt`、`lastError`。
- 不返回收件地址、令牌哈希/密文、邮件正文或完整链接。

`POST /api/v1/admin/email-jobs/{jobId}/retry`

```json
{"version": 3}
```

要求 CSRF。只接受尚未过期的 `dead` 任务，重置本轮 `attempts`、累计 `retries`，同时写入 `email.retry` 管理审计日志。状态或版本冲突返回 `409 EMAIL_RETRY_CONFLICT`；SMTP 未启用返回 `409 SMTP_DISABLED`。已发送或取消任务不能重发。重试仍执行全部发送前检查。

## 验证

测试使用独立 `gobbs_test_` PostgreSQL 数据库及仅监听回环地址的 SMTP 服务，覆盖事务失败回滚、任务去重、并发领取、租约恢复、过期清理、退避/死信/人工重试、SMTP DATA 成功而 QUIT 断开、令牌加密与失效、订阅取消和内容权限变化。实际外部 SMTP、DNS/SPF/DKIM/DMARC 和收件箱送达率需要在正式部署环境验证。
