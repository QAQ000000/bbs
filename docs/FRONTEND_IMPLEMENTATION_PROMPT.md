## 2. 已确认方向

- React + Next.js App Router + TypeScript。
- 优先采用 Arco Design React 作为基础组件库，参考 Arco Pro 的后台布局和组件组织。论坛前台按设计稿自定义，不能直接套后台模板。
- 样式优先 CSS Modules + 统一主题变量；不默认引入 shadcn/ui、Tailwind 或第二套 UI 组件库。
- 优先使用 pnpm，固定兼容版本并提交锁文件到后续待提交变更。初始化前核对官方资料中的 React、Next.js、Node 与 Arco 兼容性；不要直接假定所有最新版组合可用。
- 先用真实页面中的按钮、表单、弹层和导航验证 Arco 的 SSR、样式及移动端表现，通过后继续使用。存在实质兼容阻碍时说明证据再调整，不重新发散选型。
- Go 后端只承担 JSON API、SSE、鉴权、业务规则和受控媒体；Next.js 承担页面与渲染。
- 首页是面向中文用户的社区门户信息流，包含综合内容、关注版块、关注的人；有独立版块详情页。不是管理后台风格的卡片仪表盘。

## 5. 工程组织与基础能力

建议按项目实际规模组织，不为目录结构过度抽象：

- `frontend/src/app/`：App Router 页面、布局、加载与错误边界；前台、账号、个人和后台用合理的路由组隔离布局。
- `frontend/src/components/ui/`：确实需要统一行为的基础控件，不机械包装所有 Arco 组件。
- `frontend/src/components/forum/`：信息流、版块导航、主题正文、楼层、作者、等级 / 称号、投票与悬赏等业务组件。
- `frontend/src/components/admin/`：后台导航、列表、表单和操作反馈。
- `frontend/src/lib/api/`：服务端 / 浏览器请求适配、可信类型和错误处理。
- `frontend/src/lib/auth/`、`frontend/src/lib/markdown/`：会话与 CSRF 接入、正文与预览共用渲染规则。
- `frontend/src/styles/`：主题变量、全局样式及 Arco 覆盖。

建立最少但完整的 `dev`、`lint`、`typecheck`、`build`、`start` 命令；校验 lint 命令与选定 Next.js 版本兼容。提供 `.env.example` 和运行说明，不写入真实密钥或数据库连接串。

SSR 使用仅服务端可见的固定内部 API 地址；浏览器使用同域 `/api/v1`。开发代理正确转发 Cookie、CSRF、上传、受控媒体和 SSE，媒体路径依据现有后端契约配置。先检查本地服务和端口，不假定之前的 `localhost:33824` 仍然可用，不覆盖其他任务的服务。

先完成主题变量、前后台布局、请求层、会话初始化及公共正文渲染，再以具体页面验证。无需预先引入复杂状态库；客户端查询缓存有实际需求时再引入，并落实账号隔离。

## 7. 必须遵守的接口与业务规则

### SSR、会话和数据隔离

- 公开首页、版块、主题首屏通过 Server Components / SSR 输出真实内容，不能只在 `useEffect` 拉取。禁用 JS 后当前页正文、普通链接和分页仍可阅读使用。
- 不将整个应用统一标为客户端组件；编辑器、弹窗等按需使用客户端边界。
- 第一版关闭包含业务数据的共享整页缓存；Cookie、用户、CSRF、私信、通知、个人能力和后台响应按请求 / 账号隔离，不放入模块级共享状态。
- 复用现有 HttpOnly Cookie 会话，不改为 JWT / localStorage 登录方案。先读取 `/api/v1/session`；写入保留 Cookie 并带 `X-CSRF-Token`，登录和退出后重新同步会话。
- SSR 的内部 fetch 不会自动把 `Set-Cookie` 传给浏览器；优先让浏览器直接完成会话初始化和认证，必要的 Cookie 转发显式处理。
- 内部上游地址来自可信配置，不由请求 Host 或用户参数拼接。用户可见环境变量不包含内部凭据。
- 401、403、404、409、429、关闭站点、尚未安装、初始密码修改和 2FA 状态按真实错误码处理。页面不存在应为真实 404，不能一律返回成功空页。

### 权限、正文与写入

- 不直连 PostgreSQL，不把会员升级、积分、称号、悬赏、审核或权限算法搬到前端 / Next.js 服务端。
- 资源 ID 始终按十进制字符串处理，避免 JavaScript Number 精度丢失。
- 依据真实 DTO 和 capabilities 显示按钮，写入后以服务端结果为准；后端没返回的能力字段不能凭空假定存在。
- 非幂等动作不通用自动重试；发帖、私信、创建及 toggle 超时后先查询实际结果，保留用户输入。幂等键仅在接口实际支持时使用。
- 编辑和后台版本冲突保留本地内容，提供刷新 / 合并流程，不盲目重放旧版本。
- Markdown 原文、SSR 正文和预览使用一致的 GFM 及安全清理规则；初版禁用原始 HTML 和危险协议。不得直接将用户原文交给 `dangerouslySetInnerHTML`。
- 图片、附件使用后端返回的受控地址及权限结果，不自行拼出绕过鉴权的资源地址。
- 服务端取数 / 预取不冒充用户阅读；阅读、浏览量和已读上报按已有独立 API 规则执行。

### 信息流、订阅、私信和 SSE

- `/home` 是概览，不是完整信息流分页接口；当前全站列表按最近回复排序时，UI 如实标注“最近活跃”，不写成算法推荐或最新发表。
- 关注版块 / 关注作者的聚合流，以及设计里的摘要、封面、热门作者等，必须先确认当前接口。若仍缺失，清晰记录依赖、提供符合语义的暂不可用状态；不要浏览器循环请求后拼成全局分页，也不要为凑 UI 擅自扩大后端产品范围。
- 后端若需小范围字段补充，先说明必要性及影响；新的聚合查询或业务模块列出具体方案，不在前端复制实现。可独立的页面继续开发，不因单一接口缺口停下整个第一批。
- 新订阅默认开启通知；保存已有偏好时不能把关闭状态重置成开启。静音、通知开关与取消订阅不同，按实际契约处理。
- 私信无需互关。发起人首条之后，在接收方回复前不能再发；回复后解除首条限制，发送频率限制仍保留。
- 屏蔽拒收和 waitingForReply、blocked 等字段按社区接入文档处理；不能据错误推断并披露“对方屏蔽了你”。发送超时不得自动重发。
- SSE 只用作数据变化提示；重连后重新读取真实状态，按 ID 去重，关闭页面或账号切换时清理连接及账号缓存。
- 只接后端已有的 SSE 通道，不能假定已有私信专用实时推送；有需要时采用有边界的刷新策略。
- 后台仅提供 API 支持的全量筛选与排序，不把当前页前端排序冒充全局排序。

### SEO 和爬虫输出

- 普通用户和搜索蜘蛛读取同一套公开 SSR HTML，提供标题、description、canonical 和实际分页链接；个人页、后台及搜索索引策略遵守分离方案。
- Markdown 文档出口属于后续范围，按既有 `/content/threads/{id}.md?page=1` 和显式 Accept 设计推进；保留分页和大小限制。
- Markdown 固定游客可见范围，不转发管理员 Cookie；不根据 UA 放宽权限。UA 分流不是默认方案，不能把过去的讨论误当成已经实现或必须开启的要求。

## 8. 验收与交付

在 `frontend/` 中运行并报告实际结果：

```bash
pnpm lint
pnpm typecheck
pnpm build
```

完成必要的主流程检查，避免扩大为新一轮后端全面审计：

1. 游客首页 → 版块 → 主题，检查直接 HTTP 返回的初始 HTML 含真实标题 / 正文 / 当前页回复；禁用 JS 后能够阅读和翻页。
2. 登录 / 注册 → 发布 → 回复，覆盖会话、CSRF、提交失败保留内容和待审反馈；使用现有测试账号或隔离测试数据。
3. 通知已读、私信首条限制 / 回复解锁 / 屏蔽、后台审核和版块保存，验证实际接入，不仅是按钮可点击。
4. 用两个账号或匿名 / 登录切换验证私有页面、查询缓存和 SSR 不串数据。
5. 1440px 与 375px 检查，并抽查中间宽度；关注中文长标题、长用户名、代码块 / 表格、弹层、手机键盘和底部导航。
6. 检查加载、空、失败、无权限、冲突、重复点击、可见键盘焦点、弹层焦点返回，以及控制台 hydration / 样式错误。

所需验证以第一批实际完成的范围为准。缺少测试账号、服务或工具时说明具体未验证部分，不把构建通过写成全部联调通过；不要删除或重置现有数据库来方便测试。
