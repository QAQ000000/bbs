## 优先处理的问题

### C01 / P1：通用设置保存失败会留下部分变更

位置：`internal/store/settings.go:120`、`internal/api/handler_admin_ops.go:528`。

`SaveSettings` 遍历键值逐条提交，没有事务；发生错误直接返回，缓存失效也不会执行。故障注入使两项配置的第二次写入失败后，数据库实际已有一项变更，读取仍命中旧缓存。若修改涉及审核、注册或上传开关，返回失败并不代表原配置完整保留；缓存到期后还可能出现延迟行为变化。

建议：整批保存和变更审计同事务；提交成功后失效缓存；配置增加版本号以拒绝覆盖过期版本。

### C02 / P1：完整表单缺少完整性校验，漏传会关闭其他开关

位置：`internal/api/handler_admin_ops.go:480`、`internal/api/dto.go:101`、`docs/API.md` 的“后台动作字段”。

读取返回 camelCase，保存沿用 snake_case。文档已经明确要求完整表单，因此这不是现有接口承诺支持局部 PATCH；缺口在于服务端没有拒绝缺字段、错字段的请求。

复现：只提交 `{"site_name":"review changed name"}` 返回 HTTP 200，同时关闭注册、审核、上传、验证码及条款同意开关，清空原有条款。照搬 GET 返回字段也不能直接作为有效保存表单使用。

建议：提供类型化配置 DTO，统一读写字段；保留完整更新时必须验证必填字段，或者显式提供保留未传字段的 PATCH。拒绝未知字段与不合法布尔值。

### C03 / P2：无效配置保存成功，生效值却回退默认

位置：`internal/api/handler_admin_ops.go:508`、`internal/store/settings.go:145`。

保存缺少数值范围及格式校验，读取阶段才判断范围。复现提交 `threads_per_page=999999` 返回 HTTP 200，数据库保存 `999999`，生效值却是默认的 20。图片、附件大小和磁盘上限存在同类读取时回退逻辑。

建议：保存前完成校验并返回 422 字段错误；读取配置应暴露配置故障，不能用默认值掩盖非法配置。

### C04 / P2：通用配置的生效反馈和审计不足

静态确认，未对本项追加运行时复现：

- `internal/store/settings.go:98` 的查询错误不向上返回，会缓存默认配置；没有独立的“读取失败”状态。
- `internal/api/server.go:56` 在创建邮件服务时从启动配置取站点名；`internal/mail/mail.go:59` 始终使用该名称生成邮件标题及落款。后台修改数据库站点名不能同步修改邮件品牌，单纯重启也不一定解决，因为邮件仍取启动配置。
- `internal/api/handler_post.go:350` 的邮箱验证实际闸门同时依赖 SMTP；后台 settings 返回所保存的开关，公共 site 返回实际 `emailVerificationRequired`，后台缺少统一的配置值、实际值与不可用原因说明。
- 通用设置没有版本冲突检测，审计仅记录“更新站点设置”，没有前后差异，也没有配置版本历史与回退接口。会员、称号和积分的版本控制不能推断到通用设置上。

## 后续建议

1. 通用配置基础本批次已实现；后续根据需要补配置历史与回退、角色矩阵版本保护，并接入独立前端。
2. 将需要运营调整的内容规则、账号频控、私信额度、订阅渠道和通知保留期分组配置，并扩充对应会员权限。保留已确认的“订阅后默认通知”“首条私信等待回复”“屏蔽后拒绝发送”规则。
3. 增加安全与邮件运维接口：按角色强制 2FA、设备撤销、SMTP 状态诊断/测试邮件、队列暂停和速率控制；密码或密钥只提供脱敏状态，不通过普通配置 GET 返回。直接查看所有私人消息不应作为默认后台能力。
