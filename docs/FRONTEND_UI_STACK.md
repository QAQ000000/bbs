# React 前端 UI 与配套选型

日期：2026-09-30。React + Next.js App Router + TypeScript 已获确认并在 `frontend/` 实现，Go 继续提供业务 API。社区门户式首页、关注信息流、版块详情页和 Ardot 蓝色视觉基线已完成主要页面联调。Arco Design React 已作为基础组件库使用；编辑器增强、深色模式和更多组件抽象仍属于后续优化。实际页面清单、视觉核对和 API 差异见 [Ardot 设计核对](ARDOT_DESIGN_REVIEW.md) 与 [前端状态](FRONTEND_STATUS.md)。

| TDesign React | 桌面端 React 组件、主题定制、深色模式、Starter | 对照中文表单和窄屏行为，不能把桌面组件等同于完整移动端方案 |

### 根据首版稿件的选型判断

这张稿件的主要视觉由页面网格、主题摘要列表、头像 / 等级徽章、公告区和主题变量决定，基础控件数量有限。因此不建议为了首页引入一套会强行改变信息流观感的重型页面模板。候选库按以下顺序做最小样板：

1. 用所选库实现发布按钮、信息流标签、搜索框、公告列表、快捷入口和一个弹窗。
2. 用 CSS Modules / 主题变量自行实现三栏布局、主题摘要行、作者徽章和手机单列布局。
3. 再用相同变量实现后台表单和表格，观察是否需要保留同一套库。
4. 对比样板中的中文字体、边框、按钮高度、表单校验、弹层定位、SSR 样式和移动端行为。

当前判断：Arco Design React 作为首选基础库，Arco Pro 用于参考主题变量、导航和后台工作台能力；不直接把 Arco Pro 后台模板套到论坛首页。论坛信息流、版块页和楼层由项目自行排版。最终仍需用最小样板验证 Next.js SSR 样式、主题覆盖、弹层定位和手机行为；若验证失败，再切换 TDesign 或 Semi。


不再默认采用 shadcn/ui，也不因此否定其可定制能力。已有方案中的 Tailwind、Radix、React Hook Form、TanStack Table 和 next-themes 均需在最终组合下重新判断必要性。

## 已确认的页面方向

用户选择社区门户式，首页以信息流为主，参考头条的内容浏览形式，提供关注版块的主题、关注的人发布的主题，并保留详细的版块页面。这里确认的是页面组织方式，不代表要求复制头条视觉、开发个性化推荐算法或广告系统。

### 首页信息流

建议以三个标签组织：首页综合、关注的版块、关注的人。标签命名与是否增加独立“最新”入口在样板上确认。

| 区域 | 建议内容与行为 |
| --- | --- |
| 顶部导航 | 站点标识、搜索、首页、版块入口、发布、通知、私信与个人菜单 |
| 左侧导航 | 版块分类与常用入口；宽度不足时收为导航入口 |
| 中央信息流 | 综合 / 关注的版块 / 关注的人；主题标题、可选摘要和配图、作者、所属版块、时间与互动计数 |
| 右侧社区区域 | 公告、发帖入口、精选版块；热榜、签到或个人成长区域按需要接入，不要求首屏全部堆放 |
| 移动端 | 单列信息流，顶部保留流切换与搜索，版块及个人入口精简排列 |

信息流是连续内容列表，可用分隔线、轻量内容块组织；图片按实际帖子内容出现，无图时采用纯文字排版。先保证中文标题、摘要与作者信息层次清晰，再调整品牌色、留白和圆角。

综合流初版可复用当前“最近活跃”主题列表，并如实标注排序；不能把最后回复排序称为最新发布或算法推荐。若要最新发表、全站热度或运营推荐，需先补齐对应聚合查询和排序规则。

关注版块展示当前用户关注版块中的可见主题；关注的人展示关注用户作为作者新发布的主题，默认不把这些用户的普通回复当作新主题推入信息流。未登录时在关注标签提供登录入口；登录但尚无关注关系时提供版块浏览 / 用户关注引导；已有关注但暂时没有可见内容时展示独立空状态。

加载方式建议首屏 SSR，之后“加载更多”或渐进式滚动追加，保留列表位置和可访问的翻页链接。公开内容无需执行 JavaScript 即可阅读当前页；个人关注流按账号隔离，不进入共享缓存或搜索索引。

### 版块详情页

建议包含版块名称、说明、版主、统计、订阅按钮、发帖入口、置顶主题和普通主题列表。可使用当前已有的最近回复、最新发表、精华和热门筛选，界面中明确热门目前按查看数排序。

版块列表保留更紧凑的主题行与分页，方便持续浏览同一版块；不要求每个版块复制首页的侧栏和推荐区域。排序切换、分页与版块 ID 写入 URL，刷新和分享可恢复同一视图。

### 主题详情页

首楼展示标题、作者、等级 / 称号及正文；回复呈现楼层、引用关系和回复操作。精华、置顶、采纳、投票与悬赏等使用已有业务数据，避免仅凭前端状态显示结果。手机端收紧作者辅助信息，正文保持易读。

前后台可共用按钮、表单、弹窗和主题变量；后台独立采用管理导航、表格与设置表单。首版渲染稿已作为视觉基线。下一步先以 Arco Design React 做最小样板，参考 Arco Pro 的主题变量与后台控件，拆出基础控件与业务布局；首页信息流、版块和楼层由项目自行排版。

## 首页接口适配：当前实现与边界

2026-09-30 按当前源码核对，关注聚合流、摘要/封面投影和公开积分榜已注册并完成前端联调；下表保留仍有效的接口约束。

| 页面需求 | 现有能力 | 待补工作 / 使用约束 |
| --- | --- | --- |
| 站点导航、公告、版块目录 | GET /api/v1/site、/home、/forums | /home 是首页概览，主题预览最多 10 条，不能作为完整信息流分页入口 |
| 全站综合主题流 | GET /api/v1/threads，可用 pagination=cursor | 当前按最后回复时间排序；现有游标仅支持默认排序，不可同时传 page 或 sort |
| 版块详情与筛选 | GET /api/v1/forums/{fid}、/threads?forumId=... | 页码模式支持 new、digest、hot；置顶与普通主题分别返回，游标模式不能沿用这些 sort 参数 |
| 关注版块的信息流 | `GET /api/v1/me/feed/forums` | 已按订阅关系聚合、统一排序和签名游标分页；通知关闭或静音不等于取消订阅 |
| 关注的人的信息流 | `GET /api/v1/me/feed/users` | 已按主题作者聚合、统一排序和签名游标分页；回复不会作为人的流条目 |
| 内容摘要与配图 | 主题列表提供 `excerpt` / `coverUrl` 批量投影 | 摘要是纯文本，封面仅接受首个站内 `/uploads/` 图片；取不到时回退纯文字卡片 |
| 公开积分榜 | `GET /api/v1/leaderboard/points` | 页面读取 Worker 快照，区分 ready/stale/unavailable；热门作者、热门话题和周期榜仍未定义 |

两类关注流统一执行可见性、审核与删除规则；按主题发布时间和 ID 倒序，并将流类型与排序纳入游标校验。关系变更或权限变化后，刷新时重新读取当前可见内容；前端按主题 ID 去重，不宣称滚动期间拥有不可变快照。

关注版块拟复用现有订阅关系，通知设置单独控制投递。静音或关闭通知不应自动从关注流移除版块，取消订阅才移除关系；具体 enabled、notifyInApp、notifyEmail 字段与信息流关系在补接口时明确定义。继续保留“新订阅默认开启通知”的既定规则。

前端不循环请求每个关注用户 / 版块后合并页面，直接使用上述聚合接口。Go 仍只输出数据，不参与页面渲染。

核对入口：[读取接口](../internal/api/handler_read.go)、[游标接口](../internal/api/thread_feed.go)、[游标查询](../internal/store/thread_feed.go)、[版块排序](../internal/store/forum.go)、[主题基础投影](../internal/api/dto.go)、[社区接入说明](FRONTEND_COMMUNITY_INTEGRATION.md)。

## 编辑与 Markdown

编辑器暂建议使用 Markdown 原文编辑、工具栏和预览，保持当前 Go 正文存储格式；此项尚未获用户确认。CodeMirror 是编辑器工具包，不是现成的论坛编辑器；仍需实现加粗、引用、代码、链接、图片、表情插入、上传进度、草稿与提交状态。

PC 支持编辑 / 预览切换，宽屏可并排；手机优先切换模式。当前推荐范围暂不包含所见即所得富文本、复杂 Word 粘贴与多人协作；最终范围随编辑体验确认。未来若改富文本，需要验证到 Markdown 的往返转换和历史内容兼容。

正文与预览共用 GFM 表格、代码块、任务列表、表情及清理规则；图片与附件遵守 Go 的受控媒体权限。原始 HTML 初版禁用；自定义插件、URL 转换和组件遵循统一安全规则。普通主题正文随 SSR HTML 输出，编辑器按需加载为客户端组件。

## API 与交互约定

- SSR 使用固定内部 API 地址，用户数据按请求隔离；浏览器业务写入同域直达 Go，并保留 Cookie / CSRF。
- 等级、积分、私信首条限制和审核规则由 Go 执行；前端根据返回能力字段显示按钮，提交时处理最终结果。
- API 资源 ID 保留字符串；类型以已审核契约为准，路由级占位不当作完整业务类型。
- 非幂等操作不使用通用自动重试；编辑冲突保留本地内容，超时按接口规则查询实际状态。
- 私信、通知等客户端缓存按账号隔离，退出或换账号清理；SSE 提示刷新，重连重新读取实际状态。
- 管理列表仅暴露 API 支持的全局筛选和排序；不能把当前页排序当作全量排序。
- 基础组件补齐中文文案、键盘操作、可见焦点、焦点返回以及加载 / 空 / 失败状态。

## 浏览器与版本

浏览器支持范围在组件库与样式方案确定后，结合 Next.js、React 和依赖的实际要求统一确认；不能沿用上一版 Tailwind 4 的要求作为整个项目已定基线。需要兼容的手机浏览器和内嵌 WebView 应在样板阶段验证。

初始化时检查所选组件库与目标 React / Next.js 版本、SSR 样式加载、客户端边界、弹窗及主题切换是否兼容。官方单个组件库支持 SSR，不等于本项目目标版本组合已验证。

Next.js、React、Node、pnpm 与依赖实际版本在建工程时一起验证，记录到 package.json、运行版本文件和锁文件。按兼容组合升级，不以 @latest 替代后续可重复安装。

## 开工顺序：视觉优先

1. 以用户认可的首版首页渲染参考和 [页面设计与外部生图提示词](FRONTEND_VISUAL_BRIEF.md) 作为视觉基线；先用 Arco Design React 实现一页最小样板，参考 Arco Pro 的主题变量，确认颜色、密度与长中文排版。
2. 按首版基线补版块页、帖子详情和手机版首页，确认密度、字号、留白、圆角、导航及图片比例。
3. 将确认稿拆为主题变量、基础交互组件和业务组件清单；以 Arco Design React 为主完成组件实现，并保留 TDesign / Semi 作为失败时的对照。默认主题相近只是参考，不能替代兼容性和功能覆盖检查。
4. 制作最小可交互 React / Next.js 样板，验证中文长内容、手机布局、键盘操作、SSR、加载与错误状态；根据真实页面修正渲染稿中的不可行细节。
5. 建立正式 frontend/ 工程和同域开发代理，接入公开浏览 API，再补两类关注内容流及样板确需的摘要 / 配图投影，完成登录、关注、发布和回复闭环。
6. 进行类型检查、构建和必要的主流程验证；当前文档与选型阶段不重跑后端完整门禁或长压测。

渲染图用于确定视觉方向，未生成的图不能作为已验收稿；图片中的控件、中文文案和交互状态仍须在实际页面中确认。图片不直接充当网页，不根据单张静态稿承诺全部页面的实现效果。

以上是早期方案记录；当前 `frontend/` 工程、依赖、开发服务和主要页面已完成，生产部署仍按 [部署手册](DEPLOY.md) 执行。
