# GoBBS 前端视觉与交互规范

本文是实现和评审前端页面时的执行契约。页面必须同时满足真实 API、权限、响应式和以下视觉规则；设计稿只作为视觉参考，不能替代接口和状态验证。

## 基线

- 技术栈：Next.js App Router、React、TypeScript、Arco Design React、CSS Modules。
- 页面容器最大宽度 `1440px`，桌面内边距 `32px`，移动端内边距 `16px`。
- 手机断点为 `768px`；必须同时检查 `1440px` 和 `375px`，并抽查中间宽度。
- 中文正文使用 `var(--font-sans)`，代码使用 `var(--font-mono)`。
- 颜色、圆角、阴影和尺寸优先使用 [theme.css](../frontend/src/styles/theme.css) 中的变量，不在页面样式中复制同一组字面量。

## 组件使用

优先复用 Arco 或现有业务组件：

| 场景 | 组件来源 |
| --- | --- |
| Button、Input、Select、Modal、Switch、Table、Pagination | Arco Design React |
| 空态、失败态、头像、徽章、面包屑 | `components/ui` |
| 主题卡、楼层、投票、悬赏、关注和订阅 | `components/forum` |
| 后台表单、列表和危险操作 | `components/admin` + Arco |

只有 Arco 和现有组件无法表达业务行为时，才新增基础组件。新增组件必须说明复用不足的原因，并补齐键盘和响应式行为。

## 交互状态

所有可操作控件按实际适用范围处理以下状态：

| 状态 | 要求 |
| --- | --- |
| 默认 | 文本、图标、边框和背景具备足够对比度 |
| Hover | 不改变布局，不让文字或图标消失 |
| Active / Selected | 与默认和 Hover 有明确区分 |
| Focus | 保留可见的 `:focus-visible` 指示，不能只依赖颜色 |
| Disabled | 不可操作且能解释原因；不能伪装成请求失败 |
| Loading | 锁定重复提交，保留按钮尺寸和上下文 |
| Success / Error | 反馈紧邻动作，错误保留用户输入 |
| 403 / 404 / 409 | 依据后端状态展示，不把权限失败当空数据，不盲目重放非幂等请求 |

## 页面状态和内容边界

- 列表、详情和表单必须明确覆盖加载、空、失败、无权限和冲突状态。
- 长中文标题、长用户名、代码块、表格和窄屏弹层不能造成横向溢出或遮挡。
- 关系状态未知时，按钮应保持不可操作；不能把请求失败推断为“未关注”或“未订阅”。
- 写操作完成后以服务端返回为准；点赞、收藏、关注、订阅、发帖、私信和设置保存不使用通用自动重试。
- SSR 页面在禁用 JavaScript 时仍应能阅读正文、访问普通链接和使用分页。

## CSS 边界

- 页面优先使用 CSS Modules；全局样式只放在 `globals.css`，主题变量只放在 `theme.css`，Arco 覆盖只放在 `arco.css`。
- 页面任务默认不得修改全局样式、主题变量或公共组件。确需修改时，必须同时检查至少一个公共页、一个认证页和一个后台页。
- 不使用第二套 UI 组件库，不为单个页面复制 Button、Modal 或表单状态样式。
- 动画遵守 `prefers-reduced-motion: reduce`；动画不能承担状态表达的唯一方式。

## 验收清单

提交前逐项记录 `PASS`、`FAIL` 或 `N/A`：

1. 1440px、768px、375px 无横向溢出。
2. 默认、Hover、Active、Focus、Disabled、Loading 状态可见且不跳动。
3. 加载、空、失败、403、404、409 状态与真实接口一致。
4. 长标题、长用户名、代码块、表格和弹层布局稳定。
5. 键盘可操作，焦点可见，弹层关闭后焦点回到触发控件。
6. 控制台无 hydration、网络未处理错误或页面异常。
7. 页面没有引入 mock 业务数据，也没有绕过后端权限或状态机。
8. 截图和运行态检查覆盖页面的桌面与移动版本。

## 给 AI 的最小任务约束

实现页面时先读取本规范、页面设计文档和真实 API 类型。优先复用现有组件；不要自行发明业务字段、权限、颜色体系或全局 CSS。完成后先输出状态验收表，再修改代码；修改公共组件或主题时，必须列出影响的页面并执行对应回归检查。
