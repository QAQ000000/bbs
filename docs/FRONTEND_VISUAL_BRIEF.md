# 社区门户设计与外部生图提示词

日期：2026-09-28。交付方式：先完成页面设计与提示词，由用户在其他生图模型中生成图片，再据选定稿比较 UI 组件库。本轮不调用生图 API，不读取对话 API 地址或密钥，不安装前端依赖。

React + Next.js + TypeScript 和社区门户信息流方向已确认。本文中的提示词是初始设计提案；用户已提供 Ardot 页面设计文件，后续实现以 Ardot 稿件为当前视觉基线。当前页面实现、接口接入和联调状态以 [前端状态](FRONTEND_STATUS.md) 为准，图片本身不代表页面或接口已实现。

## 1. 设计目标

首页以内容发现为主，提供“综合”“关注版块”“关注的人”三个信息流入口；用户可以进入独立版块页，再进入主题详情。保留版块、楼层、等级和称号带来的社区身份感，同时让中文标题与正文获得主要阅读空间。

本轮主稿采用适度紧凑、清爽的门户布局。先做一张桌面首页主稿；如需比较，再用同一内容生成更舒展的版本。选定首页后，使用它作为其他页面的风格参考，不一次生成整站拼图。

## 2. 视觉规则：提案

| 元素 | 设计建议 |
| --- | --- |
| 主题 | 首轮浅色；具体深色主题在主稿确认后另行设计 |
| 页面底色 | 浅灰 #F5F6F8 |
| 内容表面 | 白色 #FFFFFF，细分隔线 #E5E7EB，尽量少用阴影 |
| 强调色 | 亮蓝 #165DFF，用于当前导航、选中下划线和主要发布按钮；不大面积铺满强调色 |
| 文字 | 标题 #202124，正文 #44474E，辅助信息 #68707A；所有状态同时有文字或图标说明 |
| 中文字体 | 系统无衬线字体；标题与正文字重分明，避免大量极细字 |
| 首页字号 | 标题约 18–20px，摘要 14–15px，辅助信息约 13px；实际实现后检查可读性 |
| 帖子正文 | 标题约 26–28px，正文约 16px、1.75 倍行距，控制每行宽度 |
| 形状与间距 | 面板约 8px 圆角，按钮约 6px 圆角；以 4/8px 为间距步长；内容条目用分隔线组织 |
| 图标与徽章 | 简洁线性图标配必要中文名称；等级 / 称号小面积展示，同一区域避免堆满徽章 |
| 图片 | 按帖子内容出现；首页混合纯文字和带缩略图条目，不为每条主题强制配图 |

亮蓝是本轮设计建议，Ardot 稿件已采用亮蓝主题；若后续需要调整，仅在确认后修改主题变量，保持布局和文案，以便比较。



## 2.1 首版渲染参考评审

用户提供的首页稿件呈现了以下明确特征：

| 观察项 | 当前参考稿表现 | 实现基线 |
| --- | --- | --- |
| 页面骨架 | 顶部全宽导航，下面左导航 / 中央信息流 / 右侧公告与快捷入口三栏 | 桌面保持三栏；窄屏改为单列，不压缩三栏 |
| 内容重点 | 中央信息流占最大面积，主题标题、摘要、作者和回复数容易扫读 | 主题摘要卡作为业务组件，使用连续列表和细分隔线 |
| 导航 | 顶部首页 / 版块，左侧版块导航，信息流内部有三类切换 | 统一导航状态；关注版块和关注的人只在登录后显示真实数据 |
| 视觉语言 | 白色面板、浅灰页面底、亮蓝强调、轻圆角、弱阴影 | 先抽取 CSS 主题变量；不绑定某个组件库的默认色 |
| 社区感 | 头像、等级标记、公告、快捷入口和热门作者并存 | 等级 / 称号作为受控业务徽章，限制显示数量 |
| 图片使用 | 只有部分主题带缩略图，文字主题仍占主流 | 列表投影提供可选媒体摘要；无图时保持文字结构稳定 |
| 信息密度 | 信息量较丰富，但没有后台表格感 | 首页保持门户密度；版块页可以更紧凑；后台单独设计 |

当前稿件适合作为“门户信息流 + 社区运营侧栏”的设计基线。需要在实际样板中继续检查：长中文标题换行、无关注内容、未登录状态、手机底部导航、浅色背景上的细边框对比，以及通知 / 私信未读状态。

稿件中的头像、热门作者、签到、草稿、公告和示例统计属于视觉占位。它们只有在对应 API 和页面流程接通后才能作为真实功能出现；不能因为渲染图存在就新增业务承诺。

## 3. 页面设计

### 3.1 桌面首页

以约 1440px 宽的桌面视口理解布局，居中内容总宽约 1200px：左栏 176px，中栏 720px，右栏 256px，两处间距各 24px。顶部导航高约 64px，内容距导航约 24px。生图不要求严格输出 CSS 像素，重点保持比例和视觉层次。

- 顶部：占位站名“社区”，首页 / 版块入口，中部搜索，右侧发布按钮、通知、私信和个人头像。
- 左栏：版块导航，交流分享、经验教程、问题求助、生活闲聊、站务公告，以及“全部版块”。当前入口轻量高亮。
- 中栏：综合 / 关注版块 / 关注的人，选中“综合”；次一级注明“最近活跃”。下方为连续主题列表，标题优先，摘要最多两行，底部展示作者、版块、时间与回复数。
- 右栏：社区公告及小型快捷入口，包含签到、收藏、草稿。不要加入没有必要的图表和大幅宣传图。
- 初始稿：已登录状态，首屏约 5–6 条可见主题或部分条目；混合无图和少量带图内容，保留自然延续到下一屏的感觉。
- 交互约定：三个信息流标签切换数据源，列表位置可恢复；具体加载与错误状态在实际样板中验证。

“关注版块”展示所关注版块中的可见主题；“关注的人”展示关注用户发布的主题。关闭订阅通知与取消关注分开；当前实现分别使用 `/api/v1/me/feed/forums` 和 `/api/v1/me/feed/users` 聚合接口。

### 3.2 版块详情

与首页共用导航和视觉变量，主体改为主栏约 920px、右栏 256px、间距 24px。版块页突出该版块的持续讨论，不重复首页的三栏目录。

- 面包屑：首页 / 版块 / 交流分享。
- 版块头部：名称、简短说明、主题与回复统计，右侧“关注版块”“发布主题”；关注后的通知设置作为次级操作。
- 主题区：最近回复 / 最新发布 / 精华 / 热门；置顶区域两条以内，普通主题采用紧凑行。
- 主题行：标题、作者、时间、回复 / 浏览计数，少量精华或状态标记，底部普通页码分页。
- 右栏：版块规则、版主信息；减少无关推荐。

### 3.3 帖子详情

沿用两栏布局，主栏首楼优先，作者信息使用紧凑横排。

- 顶部：面包屑、标题、作者头像与名称、小型等级 / 称号、发布时间。
- 首楼：清晰中文段落与内容配图；底部点赞、收藏、回复，举报等低频操作放入更多菜单。
- 回复区：楼层号、头像、用户名、回复内容、时间与回复操作；引用使用浅灰引用块，避免整段重复正文。
- 右栏：作者资料、关注 / 私信入口、所属版块信息。避免凭视觉稿引入尚未定义的相关文章推荐功能。
- 主稿使用普通讨论帖；投票、悬赏、采纳只在对应主题类型的后续变体中出现，不同时塞入一个普通帖。

### 3.4 手机版首页

以约 390px 宽屏幕理解布局；单列信息流，页面两侧留约 16px。顶部保留站名、搜索、通知入口，下一行呈现三类信息流切换。

- 中央标题可换两行，摘要适量缩短，元信息必要时分两行。
- 有图条目的缩略图约 96×72px，空间不足时调整为标题下方图片；无图条目使用纯文字。
- 桌面版块目录通过“版块”入口访问，公告简化为一条可进入的提示。
- 底部：首页 / 版块 / 发布 / 消息 / 我的；选中首页，发布项有适度视觉强调。
- 首轮只展示正常浏览状态。未登录、无关注内容、加载和错误状态在页面样板中补齐。

继续展示“全部回复”和两条可见回复。每条有头像、用户名、楼层号、时间、正文和小型回复按钮。第一条可以写“思路很清楚，期待后续更新。”第二条包含浅灰引用块和一段回复。保持首楼与回复之间清晰的层次和分隔。

右侧是作者小资料区，提供“关注”“私信”按钮，以及“所属版块：交流分享”的简洁入口。不要加入不相关的热榜和推荐卡片。

要求：普通论坛讨论帖，中文易读，内容优先、视觉安静。不要把等级、称号、投票、悬赏、采纳等所有模块同时塞入一个帖子，不要评论气泡聊天布局、后台仪表盘、巨型图片或多页拼贴。只展示一个帖子页面，可自然延伸到截图下方。

## 9. 生图后的检查与选型

先比较内容是否清楚、信息流入口是否醒目、版块是否容易进入，再比较装饰细节。中文错字应在后续稿中单独修正；生成模型未精确执行的尺寸和字重以实际页面实现为准。

首页主稿确定后再扩展其他页面；如进行对照，一次只调整一个主要维度。最终提取颜色、间距、字体和组件清单，评估基础控件的定制成本与 React / Next.js 兼容，不要求某套组件库的默认主题和图片完全一致。

可交互样板仍需覆盖真实长内容、手机布局、未登录与空状态；这些内容已在 `frontend/` 主要页面联调中覆盖。摘要 / 封面与两类关注信息流的当前接口边界见 [前端 UI 选型](FRONTEND_UI_STACK.md)。

本文保留设计与模型无关的提示词；图片由用户在外部模型生成，页面实现以 Ardot 设计核对和 `frontend/` 运行态为准。
